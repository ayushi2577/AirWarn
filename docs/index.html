Can we warn a day ahead when a city's air will be unhealthy?

Predicting whether tomorrow's AQI will be above 200 ("Poor" or worse) from past readings in 26 Indian cities, 2015–2020, and testing honestly against the rule "tomorrow = today".

01 Question

Poor-air days harm children, older people, and people with asthma or heart disease. A one-day warning lets people stay indoors, wear masks, or reschedule outdoor activity.

Question: using a city's readings up to the end of today, can we predict whether tomorrow's AQI will be above 200, better than the simple rule "tomorrow will be like today"?

Binary classification. One row = one city on one day t; the prediction is made at the end of day t using only information from day t or earlier.

Why ML if AQI is a formula? The formula only turns today's readings into today's AQI. Tomorrow's readings do not exist yet when we predict, so the model must learn patterns from history.

02 Data

Kaggle "Air Quality Data in India (2015–2020)" (rohanrao/air-quality-data-in-india), file city_day.csv. Original source: Central Pollution Control Board (CPCB). Raw data is not in this repository.

29,531city-days, 26 cities, 16 columns
15.9%of AQI values are blank
8 citiesappear only in 2019–2020
  • Some pollutants are never measured in some cities (for example no PM10 in Lucknow).
  • The AQI column was computed by the uploader, is not capped at 500 and contains implausible values (maximum 2,049).
  • No weather data (wind, rain, temperature).
  • A row is used only if both today's and tomorrow's AQI are observed: 24,343 rows, 6,330 positive (26.0%), the same rows for every model and baseline.

Target: 1 if tomorrow's AQI is above 200, the official CPCB boundary for "Poor", "Very Poor" and "Severe". Fixed before any results, not tuned.

04 Baselines and methods

MajorityAlways "not Poor". ~74% accuracy, catches nothing.
PersistenceBad tomorrow if today's AQI > 200. The main bar to beat.
Single featureBad tomorrow if today's AQI > a tuned cutoff.
  • Logistic regression: probabilities, easy to interpret, suits a thresholded warning (cross-entropy loss).
  • Linear and RBF SVM: maximum-margin classifiers (hinge loss). One exact RBF fit took 3 seconds on ~10,000 rows, so the exact kernel was used. Platt scaling gives SVM probabilities.

Model-choice rule, written before any results: choose logistic regression unless the best SVM is better in most validation folds and clearly better on average. The SVM's PR-AUC gain was smaller than the fold-to-fold spread, and at 80% recall logistic regression had higher precision in all four folds, so logistic regression was chosen.

05 Evaluation design

  • Split by time, never shuffled. Train 2015–2018 (13,024 rows); test 2019 (6,946 rows), used once; 2020 is a stress test (pre-lockdown and lockdown).
  • Embargo day: the last day before each cutoff is dropped because its label falls inside the next period.
  • Validation: four forward-chaining half-year folds inside 2015–2018 (506 to 797 positives each), date-based rather than row-based.
  • Metrics: PR-AUC (main), precision, recall, F1, ROC-AUC. Accuracy is not used.
  • Threshold: highest precision with recall ≥ 80% on pooled validation, then frozen and never re-tuned on test.
  • Uncertainty: block bootstrap over whole weeks, since consecutive days are correlated.
  • Seen vs new cities: headline = the 18 cities seen in training; the 8 unseen cities are reported separately.
  • Flip days: days where the yes/no status changes; persistence is wrong on every one by construction.

Cost of errors: a missed bad-air day costs more than a false alarm, so the threshold targets high recall while watching precision.

07 Results

Final test, run once with frozen settings

Pick a group. The headline is 2019, seen cities. Intervals are 95% block-bootstrap intervals over weeks.

Reading the headline. At the frozen threshold logistic regression has much higher precision than persistence (0.94 vs 0.85) but lower recall (0.78 vs 0.85). The validation target was 0.80, so recall drifted: the bad-day rate fell from 33% in training to 22.6% in 2019.

Equal-recall check (post-hoc, run after seeing the test, not used to change anything): at persistence's recall of 0.849, logistic regression reached precision 0.913 vs 0.847, a gain of +6.7 points (95% interval +5.0 to +8.6). The SVM gave +6.4 (+4.6 to +8.4). Real, but modest.

09 Errors

All error analysis uses validation predictions only (2017–2018); the test year was not used.

  • Of 8,736 rows: 520 missed bad days and 90 false alarms, roughly 6 misses per false alarm.
  • When today is already bad the model catches 88% of tomorrow's bad days; when today is clean and tomorrow is bad (a flip) it catches only 12.6%.
  • Missed bad days sit close to the line (average AQI about 206 today vs 391 on caught days).
  • Several large errors come from implausible AQI values in the data, such as Ahmedabad readings above 1,000.

Recall is lowest in March to May; Diwali and crop-burning weeks in October are partly missed.

10 Limitations

  • No weather data. Wind and rain strongly affect pollution, so sudden flips are mostly missed.
  • Mostly follows today's AQI. The gain over persistence is real but modest.
  • Selection bias: a row exists only when AQI was reported on both days; if sensors fail more on bad days, used days are not a random sample.
  • Coverage: 26 monitored cities, not all of India; monitors do not cover whole cities; Mumbai's AQI is mostly blank; 8 cities never appear in training.
  • Dataset AQI was computed by the uploader, is uncapped and has implausible values.
  • Threshold drift: bad days were 33% of training but 22.6% of 2019, so recall landed at 0.78, not 0.80.
  • New cities: 2019 recall drops to 0.54 (precision stays 0.92); transfer to an unseen city is weaker.
  • 2020: performance already falls before lockdown (recall 0.69) and the lockdown period has only 32 positives, so those numbers are unreliable.
  • Correlated days: the effective sample size is smaller than the row count.
  • Cannot claim: causation, performance in other cities, or performance today. The data ends in 2020.

11 Conclusion

Deployed model: logistic regression, chosen by the rule written before results: the SVM was not clearly better and logistic regression is simpler and easier to explain.

Against persistence it raises far fewer false alarms at the frozen threshold, and has about 6.7 points higher precision at equal recall. Its main weakness is that it catches only about 10% of days where clean air turns bad. Because a missed warning costs more than a false alarm, running it at a lower threshold (see the explorer) is the sensible choice, accepting more false alarms for more caught bad days.

A modest, honestly measured gain over a strong baseline is the result.

12 Reproduction steps

  1. Download city_day.csv (kaggle datasets download -d rohanrao/air-quality-data-in-india) into data/raw/. Raw data is not committed.
  2. Create a virtual environment and install requirements.txt.
  3. Run in order: data.py, splits.py, python -m pytest tests, baseline.py, models.py, run_svm.py, compare.py, run_eval.py, run_bootstrap.py, run_tables.py, run_regularization.py, run_ablation.py, run_errors.py (all in src/).
  4. With outputs/results/frozen_settings.json unchanged, run run_final_test.py and run_equal_recall.py once, then export_site_data.py.
  5. Split dates: train 2015-01-01 to 2018-12-30; test 2019-01-01 to 2019-12-30; 2020 pre-lockdown to 2020-03-23; lockdown 2020-03-25 to 2020-07-01. Embargo days: 2018-12-31, 2019-12-31, 2020-03-24.
